# Story 3.4: Processing Status Display

## Status
**Done**

## Story
**As a** user,
**I want** to see real-time progress while my declaration is being processed,
**so that** I know the system is working and how long it will take.

## Acceptance Criteria
1. Processing status screen (`/declarations/[id]`) polls `GET /api/declarations/{id}/status` every 2 seconds
2. Progress indicator shows current stage: Uploading → OCR Processing → AI Extraction → Validation → Generating Excel → Ready for Review
3. Visual progress bar or stepper component indicates completion percentage
4. Estimated time remaining displayed (based on average processing time, initially ~90 seconds)
5. Status updates in real-time as backend progresses through Celery task states
6. When status changes to READY_FOR_REVIEW, auto-redirect to review screen or show "Review Declaration" button
7. If status changes to FAILED, display error message and option to re-upload or contact support
8. User can navigate away and return; processing continues in background (per NFR20)
9. If status = FAILED, user can click "Retry Processing" button to re-queue declaration for processing
10. After 3 consecutive failed processing attempts, system displays "Contact Support" message with error ID for troubleshooting

#### Data Models (from docs/architecture/data-models.md)

**DeclarationStatus Enum:**
- `UPLOADED` - Files uploaded, not yet processing
- `PROCESSING` - OCR and LLM extraction in progress
- `VALIDATING` - Cross-document validation running
- `READY_FOR_REVIEW` - Processing complete, ready for user review
- `APPROVED` - User approved declaration
- `REJECTED` - User rejected declaration
- `FAILED` - Processing failed with error

**ProcessingStage Enum (Frontend-only, maps to backend status):**
- `UPLOADING` (map from UPLOADED status)
- `OCR_PROCESSING` (map from PROCESSING status with progress < 0.3)
- `AI_EXTRACTION` (map from PROCESSING status with progress 0.3-0.7)
- `VALIDATING` (map from VALIDATING status or PROCESSING with progress > 0.7)
- `GENERATING_EXCEL` (map from VALIDATING status with progress > 0.9)
- `READY_FOR_REVIEW` (map from READY_FOR_REVIEW status)

#### Workflow Timing (from docs/architecture/core-workflows.md)

**Processing Timeline (Target <90 seconds):**
1. Upload: 5-10s (already complete when user reaches status page)
2. OCR (4 PDFs): 20-30s (progress 0.0 → 0.3)
3. LLM Extraction: 25-40s (progress 0.3 → 0.7)
4. Validation: 5-10s (progress 0.7 → 0.9)
5. Excel Generation: 3-5s (progress 0.9 → 1.0)
6. **Total**: 58-95s (average 75s)

**Polling Strategy:**
- Poll every 2 seconds while status is PROCESSING or VALIDATING
- Stop polling when status reaches terminal state (READY_FOR_REVIEW, FAILED, APPROVED, REJECTED)
- Use TanStack Query's `refetchInterval` with conditional logic based on status

[Source: docs/architecture/core-workflows.md]

#### State Management Pattern (from docs/architecture/frontend-architecture.md)

**TanStack Query for Server State (Polling):**
```typescript
// hooks/use-declaration-status.ts
export function useDeclarationStatus(id: string) {
  const query = useQuery({
    queryKey: ['declarations', id, 'status'],
    queryFn: () => apiClient.getDeclarationStatus(id),
    refetchInterval: (data) => {
      // Poll every 2s if processing
      if (data?.status === 'PROCESSING' || data?.status === 'VALIDATING') {
        return 2000;
      }
      return false; // Stop polling for terminal states
    },
    refetchOnWindowFocus: true, // Resume polling if user returns to tab
  });

  // Calculate estimated time remaining
  const estimatedTimeRemaining = useMemo(() => {
    if (!query.data?.created_at) return 90;
    const elapsed = (Date.now() - new Date(query.data.created_at).getTime()) / 1000;
    return Math.max(0, 90 - elapsed);
  }, [query.data?.created_at]);

  return { ...query, estimatedTimeRemaining };
}
```
