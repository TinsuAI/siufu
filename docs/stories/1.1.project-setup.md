### Docker Compose Service Configuration
[Source: docs/architecture/deployment-architecture.md]

**Service: postgres**
- Image: `postgres:18.0-alpine`
- Environment: `POSTGRES_DB=customs_db`, `POSTGRES_PASSWORD=${POSTGRES_PASSWORD}`
- Volume: `postgres-data:/var/lib/postgresql/data`
- Healthcheck: `pg_isready -U postgres` (interval 10s, timeout 5s, retries 5)
- Restart policy: `unless-stopped`

**Service: redis**
- Image: `redis:7.4.1-alpine`
- Volume: `redis-data:/data`
- Healthcheck: `redis-cli ping` (interval 10s, timeout 3s, retries 5)
- Restart policy: `unless-stopped`

**Service: backend**
- Build: `./backend`
- Port: `8000:8000`
- Environment: `DATABASE_URL=postgresql+asyncpg://postgres:${POSTGRES_PASSWORD}@postgres:5432/customs_db`, `REDIS_URL=redis://redis:6379/0`
- Volumes: `uploaded-files:/app/data/uploads`, `exports:/app/data/exports`
- Secrets: `gcp-sa-key` (file: `./secrets/gcp-sa-key.json`)
- Depends on: postgres (healthy), redis (healthy)
- Restart policy: `unless-stopped`

**Service: celery-worker**
- Build: `./backend`
- Command: `celery -A src.workers.celery_app worker --loglevel=info`
- Environment: `DATABASE_URL=postgresql+asyncpg://postgres:${POSTGRES_PASSWORD}@postgres:5432/customs_db`, `CELERY_BROKER_URL=redis://redis:6379/0`
- Volumes: Same as backend (`uploaded-files`, `exports`)
- Secrets: Same as backend (`gcp-sa-key`)
- Depends on: redis, postgres
- Restart policy: `unless-stopped`

**Service: frontend**
- Build: `./frontend`
- Port: `3000:3000`
- Depends on: backend
- Restart policy: `unless-stopped`

**Volumes:**
- `postgres-data` (database persistence)
- `redis-data` (cache persistence)
- `uploaded-files` (user-uploaded PDFs and Excel files)
- `exports` (generated CD.xlsx files)

**Secrets:**
- `gcp-sa-key`: Google Cloud service account JSON key file for Document AI API (user creates this in `./secrets/gcp-sa-key.json`)

### Development Workflow
[Source: docs/architecture/development-workflow.md]

**Local Setup Steps:**
1. Prerequisites: Docker Desktop 27.x+
2. Clone repository: `git clone https://github.com/client/logai.git`
3. Navigate to project: `cd logai`
4. Copy environment template: `cp .env.example .env`
5. Edit `.env` with actual API keys
6. Start all services: `docker-compose up -d`
7. Run migrations: `docker-compose exec backend alembic upgrade head`
8. Seed initial data: `docker-compose exec backend python scripts/seed-data.py`
9. Access application: Frontend at http://localhost:3000, Backend API docs at http://localhost:8000/docs
10. Login credentials (for future stories): `admin@logistics.vn / admin123`

**Common Development Commands:**
- Frontend dev (hot reload): `cd frontend && npm run dev`
- Backend dev (hot reload): `cd backend && uvicorn src.main:app --reload`
- Run frontend tests: `npm run test` (Vitest)
- Run backend tests: `pytest` (pytest)
- Run E2E tests: `playwright test`
- Generate migration: `alembic revision --autogenerate -m "Add field"`
- Apply migrations: `alembic upgrade head`
- Rollback migration: `alembic downgrade -1`
- Generate API client: `npm run generate-client` (OpenAPI TypeScript codegen)

### Coding Standards
[Source: docs/architecture/coding-standards.md]

**Critical Fullstack Rules:**
- Type Sharing: Define types in `backend/src/schemas/`, generate TypeScript types via OpenAPI
- API Calls: Never use direct `fetch()` - use generated API client
- Environment Variables: Access via `config.py` (backend) or `process.env.NEXT_PUBLIC_*` (frontend)
- Error Handling: All API routes use standard error middleware
- State Updates: Never mutate Zustand state directly

**Naming Conventions:**
- Components (frontend): PascalCase (e.g., `UserProfile.tsx`)
- Hooks (frontend): camelCase with 'use' prefix (e.g., `useAuth.ts`)
- API Routes (backend): kebab-case (e.g., `/api/user-profile`)
- Database Tables (backend): snake_case (e.g., `user_profiles`)

### Alembic Configuration Notes
[Source: docs/architecture/backend-architecture.md]

Alembic should be configured for async SQLAlchemy 2.0:
- Use `asyncpg` driver for PostgreSQL connection: `postgresql+asyncpg://...`
- Configure `env.py` to use async engine and context
- Database URL should come from environment variable (read from `config.py`)
- Initial migration creates empty database (no models yet - models will be added in Story 1.2)
