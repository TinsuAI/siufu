# Story 3.10: Master Data Management for Importers & Exporters

## Status
Done

## Story
**As a** customs processing specialist,
**I want** the system to remember and reuse importer/exporter company data across declarations,
**so that** I don't have to repeatedly review and correct the same company information, reducing processing time and improving data consistency.

## Acceptance Criteria

1. Database tables `importers` and `exporters` created with all relevant fields (tax_code, name, address, metadata, quality tracking)
2. `declarations` table has foreign keys `importer_id` and `exporter_id` to link to master data
3. During AI extraction, system checks for existing importer by tax_code match (primary) or fuzzy name match (fallback, 85% threshold)
4. If matching importer/exporter found, system uses master data instead of AI extraction and sets confidence scores to 1.0
5. Declaration form displays "✅ Verified Company" badge for known importers/exporters
6. On declaration approval, system creates or updates importer/exporter master record with corrected data
7. Companies list page (`/companies`) displays all importers and exporters with search, filter, and sort capabilities
8. Users can manually add, edit, and soft-delete companies via UI
9. Duplicate detection endpoint identifies potential duplicate companies using fuzzy matching (80% similarity threshold)
10. Merge functionality allows combining two duplicate company records and updating all linked declarations

### Matching Algorithm

**[Source: Handoff Document Section "MATCHING ALGORITHM"]**

**Importer Matching Priority:**
1. **Tax Code Match (Primary)**: Exact match on normalized tax_code (remove spaces, dashes, uppercase) - most reliable
2. **Fuzzy Name Match (Fallback)**: 85%+ Levenshtein similarity on name_normalized - fallback for data entry errors

**Exporter Matching Priority:**
1. **Exact Match**: name_normalized + country_code composite match
2. **Fuzzy Name Match**: 85%+ similarity on name_normalized within same country_code

**Normalization Functions:**
- `normalize_tax_code()`: Remove non-alphanumeric, uppercase (e.g., "0123-456-789" → "0123456789")
- `normalize_company_name()`: Lowercase, remove accents (NFKD normalization), remove special chars, collapse spaces (e.g., "Công ty TNHH ABC" → "cong ty tnhh abc")
- `calculate_similarity()`: Use `difflib.SequenceMatcher` for Levenshtein distance ratio (0.0-1.0)

**Duplicate Detection:**
- Use 80% similarity threshold (lower than matching threshold to catch more potential duplicates for manual review)
- Compare all companies pairwise within organization (O(n²) complexity - acceptable for MVP with limited companies)

### API Specifications

**[Source: Handoff Document Section "MASTER DATA MANAGEMENT UI"]**

**List Companies:**
- Endpoint: `GET /api/companies/`
- Query Params: `type` ('importers'|'exporters'), `search` (string), `filter` ('all'|'verified'|'unverified'), `page` (int, default 1), `limit` (int, default 20), `sort_by` (string), `sort_order` ('asc'|'desc')
- Response: `CompanyListResponse` (200 OK)
- Authentication: JWT required
- Filter: organization_id + deleted_at IS NULL

**Get Company:**
- Endpoint: `GET /api/companies/{id}`
- Query Param: `type`
- Response: `ImporterDetail` or `ExporterDetail` (200 OK), 404 Not Found

**Create Company:**
- Endpoint: `POST /api/companies/`
- Query Param: `type`
- Request: `ImporterCreate` or `ExporterCreate`
- Response: `ImporterDetail` or `ExporterDetail` (201 Created)
- Behavior: Normalizes tax_code and name, sets is_verified=True, organization_id

**Update Company:**
- Endpoint: `PATCH /api/companies/{id}`
- Query Param: `type`
- Request: `ImporterUpdate` or `ExporterUpdate` (partial)
- Response: `ImporterDetail` or `ExporterDetail` (200 OK)

**Delete Company:**
- Endpoint: `DELETE /api/companies/{id}`
- Query Param: `type`
- Response: 204 No Content
- Behavior: Soft delete (set deleted_at)

**Find Duplicates:**
- Endpoint: `GET /api/companies/duplicates`
- Query Param: `type`
- Response: `List[DuplicatePair]` (200 OK)
- Algorithm: Compare all companies pairwise, return pairs with 80%+ similarity

**Merge Companies:**
- Endpoint: `POST /api/companies/merge`
- Query Param: `type`
- Request: `MergeRequest` (keep_id, merge_id)
- Response: `ImporterDetail` or `ExporterDetail` (200 OK)
- Behavior: Update declarations, increment declaration_count, soft delete merged company
