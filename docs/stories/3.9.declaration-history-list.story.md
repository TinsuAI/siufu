# Story 3.9: Declaration History List

## Status
Ready for Review

## Story
**As a** user,
**I want** to see a list of all my processed declarations,
**so that** I can track my work and re-download previous exports.

## Acceptance Criteria
1. Declarations list screen (`/declarations`) displays table of all declarations for authenticated user
2. Table columns: Declaration ID, Upload Date, Status (Uploaded/Processing/Ready/Approved/Rejected), Products Count, Actions
3. Status badge color-coded: Gray (Uploaded), Blue (Processing), Green (Approved), Red (Rejected)
4. Sortable by Upload Date (default: newest first) and Status
5. Searchable by Declaration ID
6. Actions column includes: "Review" button (for Ready/Approved), "Download" button (for Approved), "Delete" button (soft delete)
7. Pagination: 20 declarations per page
8. Clicking "Review" navigates to `/declarations/[id]/review`
9. Clicking "Download" re-downloads Excel file (no re-processing needed)
10. API endpoint `GET /api/declarations` returns paginated, filtered list

### API Specifications
**[Source: architecture/api-specification.md]**

**List Declarations:**
- Endpoint: `GET /api/declarations`
- Query Parameters:
  - `page` (integer, default: 1) - Page number
  - `limit` (integer, default: 20) - Items per page
  - `status` (string, optional) - Filter by status (e.g., "APPROVED")
  - `search` (string, optional) - Search by declaration ID (partial match)
  - `sort_by` (string, default: "created_at") - Sort field (created_at or status)
  - `sort_order` (string, default: "desc") - Sort direction (asc or desc)
- Response: `DeclarationListResponse` (200 OK)
- Status codes: 200 OK, 400 Bad Request (invalid params), 401 Unauthorized
- Authentication: JWT token required (httpOnly cookie or Authorization header)
- Filter behavior: Users only see declarations where `created_by_user_id` matches authenticated user
- Soft delete: Exclude declarations where `deleted_at IS NOT NULL`

**Delete Declaration (Soft Delete):**
- Endpoint: `DELETE /api/declarations/{id}`
- Request: No body required
- Response: 204 No Content (successful deletion)
- Status codes: 204 No Content, 404 Not Found, 403 Forbidden (user doesn't own declaration)
- Behavior: Sets `deleted_at` timestamp instead of hard delete (audit trail preserved)
- Authorization: User can only delete their own declarations

**Export Declaration (Reused from Story 3.8):**
- Endpoint: `GET /api/declarations/{id}/export`
- Response: File download (Excel file)
- No re-processing: Returns cached file from `./data/exports/{declaration_id}/CD.xlsx`

### Security Considerations
**[Source: architecture/tech-stack.md + architecture/coding-standards.md]**
- All API endpoints require JWT authentication (validate `get_current_user`)
- User isolation: Backend filters declarations by `created_by_user_id` (users only see their own data)
- Soft delete authorization: Users can only delete their own declarations (403 Forbidden if mismatch)
- No XSS risk: All data sanitized by Pydantic schemas and React escapes HTML by default
- Rate limiting: 100 requests/minute per user (soft limit for MVP)
- SQL injection protection: SQLAlchemy ORM with parameterized queries

### Performance Considerations
- Pagination reduces database load: Only fetch 20 declarations per page (not all declarations at once)
- List endpoint excludes large fields (`extracted_data`, `draft_data`, `uploaded_files`) for faster response
- TanStack Query caching: Reduces redundant API calls when navigating between pages
- Search debouncing: 500ms delay reduces API calls while user is typing
- Database indexes: Index on `created_by_user_id`, `status`, `created_at`, `deleted_at` for fast filtering/sorting
- Soft delete query: `WHERE deleted_at IS NULL` uses index for fast filtering
