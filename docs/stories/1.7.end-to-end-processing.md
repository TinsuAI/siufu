# Story 1.7: Process Complete Declaration End-to-End

## Status
Ready for Review

## Story

**As a** developer,
**I want** to trigger end-to-end processing that calls OCR, LLM extraction, and stores results,
**so that** I can verify the complete AI extraction pipeline works with real sample data.

## Acceptance Criteria

1. API endpoint `POST /api/declarations/{id}/process` triggers Celery task for given declaration
2. Task processes all 4 document files (AN, BOL, CO, INVOICE) through Google Document AI OCR
3. OCR results for all 4 documents passed to GPT-5 extraction with comprehensive prompt
4. Extracted data (JSON) includes ALL 77 fields required for Vietnamese customs declaration form as defined in `docs/stories/1.7-field-mapping.md`:
   - Declaration header (6 fields): declaration number, type code, customs office, etc.
   - Importer information (5 fields): tax code, name, address, phone, postal code
   - Exporter information (5 fields): name, full address, country code
   - Shipping & transport (10 fields): B/L number, ports, vessel, arrival date, warehouse
   - Package & container (6 fields): total packages, gross weight, container count
   - Invoice information (8 fields): invoice number, date, total, currency, incoterm, exchange rate
   - Certificate of Origin (3 fields): CO form type, number, date
   - Product line items (18 fields per product): HS code, description, quantities, prices, origin
   - Tax calculation - Import duty (4 fields): rate, rate type, amount, exemptions
   - Tax calculation - VAT (6 fields): rate, rate code, taxable value, amount
   - Tax summary (4 fields): total tax amount, payment deadline, taxpayer type
   - Metadata (2 fields): total pages, total line items
   - **Critical mandatory fields (58)** must have confidence ≥0.70
5. Each extracted field includes confidence score from LLM
6. Processing completes within 240 seconds for sample declarations (per NFR1 - revised 2025-10-22 from 90s based on actual LLM performance)
7. Results stored in database and accessible via `GET /api/declarations/{id}` endpoint
8. Successfully processes all 3 sample declarations from `resources/sample/1/`, `resources/sample/2/`, `resources/sample/3/`
9. Extracted data matches expected values from manual review of sample files (accuracy validation)

### Architecture Context - Complete Processing Workflow

[Source: docs/architecture/core-workflows.md]

**Workflow 1: Complete Declaration Processing (Happy Path)**

The end-to-end processing follows this sequence:

```
1. User uploads 6 files � Declaration created with status UPLOADED
2. User triggers processing � Celery task queued
3. Celery worker processes:
   a. OCR Processing (20-30s):
      - Process AN.pdf, BOL.pdf, CO.pdf, INVOICE.pdf in parallel
      - Cache results in Redis (24hr TTL)
      - Update status: PROCESSING_OCR, progress: 0.2
   b. LLM Extraction (25-40s):
      - Send all 4 OCR results to GPT-5 with comprehensive prompt
      - Parse JSON response
      - Extract confidence scores
      - Update status: PROCESSING_LLM, progress: 0.6
   c. Store Results (1-2s):
      - Update declaration.extracted_data
      - Update declaration.confidence_scores
      - Update status: READY_FOR_REVIEW, progress: 1.0
4. Frontend polls status � Auto-redirects to review screen
```

**Target Timing Breakdown (NFR1: <90 seconds):**
- OCR (4 PDFs): 20-30s
- LLM Extraction: 25-40s
- Data Storage: 1-2s
- **Total**: 46-72s (avg 59s, well under 90s target)

### API Specification

[Source: docs/architecture/api-specification.md]

**POST /api/declarations/{id}/process**
- **Purpose**: Trigger async processing for uploaded declaration
- **Auth**: JWT required
- **Request**: Empty body
- **Response** (202 Accepted):
  ```json
  {
    "declaration_id": "uuid",
    "status": "PENDING_PROCESSING",
    "celery_task_id": "task-uuid",
    "message": "Processing started. Poll /api/declarations/{id}/status for updates."
  }
  ```
- **Errors**:
  - 404: Declaration not found
  - 400: Declaration status not UPLOADED (cannot reprocess)
  - 503: Celery worker unavailable

- **Purpose**: Retrieve complete declaration details
- **Auth**: JWT required
- **Response** (200 OK):

    "id": "uuid",
    "status": "READY_FOR_REVIEW",
    "uploaded_files": [...],
    "extracted_data": {
      "shipper": {...},

### Critical Implementation Notes

**LLM Prompt Engineering Best Practices:**
- Explicitly specify JSON structure in prompt
- Provide examples of desired output format
- Handle Vietnamese text: Instruct LLM to preserve Vietnamese characters
- Conflict resolution: Instruct LLM which document takes precedence (e.g., Invoice total > CO total if mismatch)
- Confidence scoring: Instruct LLM to assign lower confidence if data is ambiguous or partially extracted

**Error Handling Strategy:**
- **Transient Errors** (429, 503 from external APIs): Retry with exponential backoff
- **Permanent Errors** (400, 401 from external APIs): Fail immediately, log to Sentry
- **Data Validation Errors**: Mark declaration as FAILED with specific error message
- **Database Errors**: Rollback transaction, mark Celery task as FAILED

**Performance Optimization:**
- **Parallel OCR**: Use `asyncio.gather()` to process 4 documents simultaneously (saves ~15s)
- **Redis Caching**: Cache OCR results to avoid redundant API calls on reprocess
- **Connection Pooling**: Reuse HTTP connections to external APIs (reduce latency)
- **Async I/O**: All file operations use `aiofiles` to prevent blocking
