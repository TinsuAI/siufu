# Story 3.11: Cross-Document Income Validation - Brownfield Addition

## Status
Done

## Story

**As a** customs processing specialist,
**I want** the system to automatically validate consistency across all uploaded declaration documents (AN, BOL, CO, INVOICE),
**so that** I can quickly identify discrepancies, typos, and data quality issues before final review, reducing errors and processing time.

4. **Non-blocking behavior**: Validation warnings do not prevent workflow from continuing to READY_FOR_REVIEW

### Validation Rules to Implement (16 Total)

**Priority 1: Critical Consistency Checks (5 rules)**
1. **Quantity mismatches**: Product quantities differ between Invoice and CO
   - Severity: error
   - Compare `products[i].quantity_1` across documents
2. **Amount discrepancies**: Invoice total ≠ sum of product line totals
   - Severity: error
   - Tolerance: ±1% for rounding
   - Formula: `abs(invoice.invoice_total - sum(products.invoice_line_total)) / invoice.invoice_total > 0.01`
3. **Name variations**: Importer/Exporter names spelled differently across documents
   - Severity: warning
   - Use fuzzy match, 90% threshold (stricter than master data's 85%)
4. **HS code mismatches**: Different HS codes for same product across documents
   - Severity: error
   - Compare by product description similarity
5. **Tax calculation errors**: VAT or import duty amounts don't match calculated values
   - Severity: error
   - Tolerance: ±1%
   - Formula: `abs(actual_tax - (taxable_value * rate)) / actual_tax > 0.01`

**Priority 2: Date & Reference Validation (3 rules)**
6. **Date inconsistencies**: Invoice date after arrival date
   - Severity: warning
   - Check: `invoice.invoice_date > shipping_transport.arrival_date`
7. **Document date sequence**: Logical progression
   - Severity: warning
   - Check: `invoice.invoice_date <= shipping_transport.arrival_date`
8. **Reference number cross-check**: BOL number matches
   - Severity: error
   - Compare: `shipping_transport.bill_of_lading_number` vs Invoice reference

**Priority 3: Data Quality Checks (4 rules)**
9. **Missing data cross-reference**: Product in Invoice but not in CO
   - Severity: warning
   - Match products by description similarity
10. **Currency confusion**: Mixed currencies without exchange rate
    - Severity: error
    - Check all `invoice_unit_price_currency` values are same or exchange_rate exists
11. **Product count mismatch**: Number of line items differs
    - Severity: info
    - Compare `len(products)` from Invoice vs CO
12. **Container/Package consistency**: Container count consistent
    - Severity: info
    - Check: `package_container.container_count` vs BOL containers

**Priority 4: Sanity Checks (4 rules)**
13. **Weight verification**: Gross weight aligns with product quantities
    - Severity: info
    - Basic sanity: weight > 0, reasonable per-item weight
14. **Port consistency**: Port of loading aligns with exporter country
    - Severity: info
    - Check: `shipping_transport.port_of_loading_code` country vs `exporter.country_code`
15. **Tax rate validation**: Rates are reasonable
    - Severity: warning
    - Check: `0 <= rate <= 100` for VAT and import duty
16. **Duplicate detection**: Check for duplicate product lines
    - Severity: warning
    - Compare products by HS code and description

### Validation Warning Structure

```python
{
    "field": str,              # e.g., "products[0].quantity_1", "invoice.invoice_total"
    "severity": str,           # "error" | "warning" | "info"
    "message": str,            # Human-readable message for users
    "rule": str,               # Rule identifier e.g., "quantity_mismatch", "amount_discrepancy"
    "details": {
        "source_docs": List[str],      # e.g., ["INVOICE", "CO"] - which documents are involved
        "expected_value": Any,          # e.g., 1000 - what we expected to see
        "actual_value": Any,            # e.g., 900 - what we actually found
        "confidence": float             # 0.0-1.0 - how confident we are in this warning
    }
}
```

### Key Constraints & Performance

- **Performance**: Must not increase processing time by more than 5 seconds
  - Target total pipeline: <90 seconds (NFR1 requirement)
  - Current pipeline: ~60-80 seconds
  - Validation budget: <5 seconds
- **Multiple CO files**: Handle 1-20 CO files correctly (Story 3.3.1 requirement)
- **Null handling**: Gracefully handle missing or null fields in extracted data
- **Organization scoping**: Only validate within user's organization data (no cross-org leaks)
- **Error tolerance**: Use ±1% tolerance for amount/tax calculations to avoid false positives
- **Fuzzy matching**: Use 90% threshold for name comparisons (stricter than master data's 85%)

### Security Considerations

- Validation only accesses declaration data within user's organization (organization_id scoped)
- No sensitive data logged in validation warnings (only field references and anonymized values)
- Confidence scores do not expose internal algorithm details
- localStorage for dismiss functionality is session/browser specific (no backend persistence)
