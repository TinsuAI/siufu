# Story 1.6: File Upload and Storage

## Status
Done

## Story

**As a** user,
**I want** to upload all 6 required files for a customs declaration,
**so that** the system can begin processing my declaration.

## Acceptance Criteria

1. API endpoint `POST /api/declarations/upload` accepts multipart form data with 6 files
2. Validates file types: AN.pdf, BOL.pdf, CO.pdf (must be PDF), INVOICE (PDF or JPG/PNG), goodlist (XLS/XLSX), tariff (XLS/XLSX)
3. Validates all 6 files are present before accepting upload (per FR1)
4. Files stored in Docker volume at `./data/uploads/{declaration_id}/` with original filenames preserved
5. Declaration record created in database with status UPLOADED and references to file paths
6. Returns declaration ID and status to frontend for tracking
7. File size limits enforced: PDFs max 10MB, images max 5MB, Excel files max 2MB
8. Clear error messages returned if validation fails (missing files, wrong types, size exceeded)

### File Type Validation Rules

**PDF Files (AN, BOL, CO, INVOICE):**
- MIME type: `application/pdf`
- Magic bytes: `25 50 44 46` (starts with "%PDF")
- Max size: 10MB (10,485,760 bytes)

**Image Files (INVOICE alternative):**
- MIME types: `image/jpeg`, `image/png`
- Magic bytes: `FF D8 FF` (JPEG) or `89 50 4E 47` (PNG)
- Max size: 5MB (5,242,880 bytes)

**Excel Files (goodlist, tariff):**
- MIME types:
  - `.xls`: `application/vnd.ms-excel`
  - `.xlsx`: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- Magic bytes:
  - `.xls`: `D0 CF 11 E0 A1 B1 1A E1` (OLE2)
  - `.xlsx`: `50 4B 03 04` (ZIP archive)
- Max size: 2MB (2,097,152 bytes)

### Security Considerations

[Source: docs/architecture/coding-standards.md, docs/prd/technical-assumptions.md]

**File Upload Security:**
- **Validate file types using magic bytes**, not just Content-Type header (prevents MIME type spoofing)
- **Enforce file size limits** to prevent disk exhaustion attacks
- **Use unique UUID directories** to prevent path traversal attacks
- **Sanitize filenames** to remove special characters (`.`, `..`, `/`, `\`)
- **Atomic file writes** to prevent corrupted files (write to temp, then rename)
- **Limit upload rate** to prevent DoS (100 requests/minute per user)
- **Virus scanning**: Consider future integration with ClamAV for malware detection (Story 4.x)

### Performance Considerations

**Upload Performance:**
- Target: Upload 6 files (total ~20MB) in <10 seconds over typical office network
- Use streaming uploads (FastAPI UploadFile) to avoid loading entire files into memory
- Async file I/O (aiofiles) prevents blocking event loop during disk writes

### Security Review

✅ **Excellent security implementation:**

**Strengths:**
1. **Magic Byte Validation**: Uses python-magic to verify actual file content, preventing MIME type spoofing attacks
2. **Filename Sanitization**: Removes path traversal characters (`.`, `..`, `/`, `\`, etc.)
3. **Size Limits**: Prevents disk exhaustion (PDFs 10MB, images 5MB, Excel 2MB)
4. **Unique UUID Directories**: Prevents path collisions and unauthorized access
5. **Atomic Writes**: Prevents file corruption from interrupted writes
6. **Proper File Permissions**: Files set to 0o644 (read for all, write for owner)
7. **Transactional Uploads**: Automatic cleanup on failures prevents orphaned files
