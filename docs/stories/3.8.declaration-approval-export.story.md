# Story 3.8: Declaration Approval & Export

## Status
Done

## Story
**As a** user,
**I want** to approve the reviewed declaration and download the final Excel file,
**so that** I can submit it to customs (per FR14, FR9).

## Acceptance Criteria
1. Review screen header contains sticky "Approve" and "Reject" buttons visible while scrolling
2. "Approve" button disabled if unsaved changes exist (show tooltip: "Please wait for auto-save to complete")
3. Clicking "Approve" sends `POST /api/declarations/{id}/approve` request
4. Backend updates Declaration status to APPROVED and records approving user ID and timestamp (per FR20)
5. On approval success, "Download Excel" button appears
6. Clicking "Download Excel" triggers download of `CD.xlsx` file from `GET /api/declarations/{id}/export`
7. Excel file downloads within 5 seconds (per NFR3)
8. After download, confirmation message: "Declaration approved and exported successfully"
9. "Reject" button marks Declaration as REJECTED and prompts user for rejection reason
10. Rejected declarations moved to "Rejected" list, can be re-opened and re-processed

### API Specifications
**[Source: architecture/rest-api-spec.md + backend/src/api/v1/declarations.py]**

**Approve Declaration:**
- Endpoint: `POST /api/declarations/{id}/approve`
- Request: No body required (user context from JWT)
- Response: `DeclarationApproveResponse` with updated status and approval details
- Status codes: 200 OK, 404 Not Found, 400 Bad Request (invalid status transition)

**Reject Declaration:**
- Endpoint: `POST /api/declarations/{id}/reject`
- Request: `{ rejection_reason: string }` (min 10 chars)
- Response: `DeclarationRejectResponse` with updated status
- Status codes: 200 OK, 404 Not Found, 400 Bad Request (missing reason or invalid status)

**Export Declaration to Excel:**
- Endpoint: `GET /api/declarations/{id}/export`
- Response: File download (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)
- Headers: `Content-Disposition: attachment; filename="CD_{declaration_id}.xlsx"`
- Status codes: 200 OK, 404 Not Found (file not generated), 403 Forbidden (not approved yet)

**Authentication:**
- All endpoints require JWT token in cookie or Authorization header
- Current user context extracted via `get_current_user` dependency from `src.core.deps`

### Security Considerations
**[Source: architecture/tech-stack.md + architecture/coding-standards.md]**
- All API endpoints require JWT authentication (validate `get_current_user`)
- Only the authenticated user can approve declarations (audit trail with `approved_by_user_id`)
- Rejection reason is stored in database (audit trail for compliance)
- File download requires APPROVED status (cannot download unapproved declarations)
- No XSS risk: All data sanitized by Pydantic schemas
- File download uses secure headers: `Content-Disposition: attachment` (prevents inline execution)

### Performance Considerations
- Excel file download must complete within 5 seconds (NFR3)
- File is served from Docker volume (fast local disk I/O)
- Export endpoint uses streaming FileResponse (no memory buffering)
- Approval status update is a single database transaction (fast)
- TanStack Query cache invalidation triggers automatic refetch on declarations list
