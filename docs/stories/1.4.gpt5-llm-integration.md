# Story 1.4: GPT-5 LLM Integration via OpenRouter

## Status
Done

## Story

**As a** developer,
**I want** integration with GPT-5 via OpenRouter for intelligent data extraction from OCR results,
**so that** the system can understand and extract structured customs data regardless of document format variations.

## Acceptance Criteria

1. OpenRouter API client configured with API key from environment variables
2. Service supports three model tiers: `openai/gpt-5` (Flagship), `openai/gpt-5-mini` (Mini), `openai/gpt-5-nano` (Nano)
3. Function `extract_structured_data(ocr_result: OCRResult, model: str) -> ExtractedData` sends OCR text to GPT-5 with extraction prompt
4. Extraction prompt instructs GPT-5 to extract: product descriptions, quantities, prices, HS codes, company names, dates, container numbers, weights
5. LLM response parsed as JSON with per-field confidence scores
6. Temperature set to 0.1 for deterministic extraction
7. Retry logic with exponential backoff for transient API failures
8. Unit tests mock OpenRouter API to avoid costs and ensure deterministic testing

### Tech Stack - OpenRouter Integration

[Source: architecture/tech-stack.md, architecture/external-apis.md]

**OpenRouter API Details:**
- **Base URL**: `https://openrouter.ai/api/v1`
- **Authentication**: API Key in `Authorization: Bearer {key}` header
- **Recommended HTTP Client**: `httpx` (async support, connection pooling, timeout handling)
- **API Compatibility**: OpenRouter uses OpenAI-compatible API format (same request/response structure)

**Model Tier Strategy:**
| Model | Cost/1M Tokens (Input/Output) | Use Case |
|-------|-------------------------------|----------|
| `openai/gpt-5` (Flagship) | ~$15 / ~$60 | Complex multi-document extraction, conflict resolution |
| `openai/gpt-5-mini` (Mini) | ~$0.15 / ~$0.60 | Simple field extraction, dates, company names |
| `openai/gpt-5-nano` (Nano) | ~$0.05 / ~$0.20 | Validation tasks, format checking |

**Cost Estimation per Declaration:**
- Average declaration: ~1,200 prompt tokens (OCR text) + ~800 completion tokens (JSON output)
- Flagship model: (1200 × $15 + 800 × $60) / 1,000,000 = **$0.025/declaration**
- Mini model: (1200 × $0.15 + 800 × $0.60) / 1,000,000 = **$0.0006/declaration**
- **Target**: Use Flagship for MVP (best accuracy), optimize to Mini in Phase 2

**Rate Limits:**
- OpenRouter default: 60 requests/minute
- Burst handling: Exponential backoff if rate limited
- Cost control: No per-request cost limit needed (each request ~$0.025, well under budget)

**Integration Best Practices:**
- Set `HTTP-Referer` header for OpenRouter analytics
- Set `X-Title` header to identify application
- Handle streaming responses if implementing real-time extraction UI (Phase 2)
- Log token usage for every request (cost tracking critical)

```python
class OCRResult(BaseModel):
```

- **Tables**: Format `ocr_result.tables` as markdown tables in prompt (LLMs parse markdown tables well)
- **Multi-document context**: When processing full declaration, concatenate OCR results from all 4 documents with clear section headers

### ExtractedData Schema Design

[Source: Acceptance Criteria 4, 5]

**Schema Requirements:**
```python
# backend/src/schemas/extraction.py

class CompanyDetails(BaseModel):
    """Shipper or Consignee company information"""
    name: str | None = None
    address: str | None = None
    tax_id: str | None = None  # Vietnam: MST (Ma So Thue)
    contact_person: str | None = None
    phone: str | None = None
    confidence: float = Field(ge=0.0, le=1.0, default=0.0)

class ProductItem(BaseModel):
    """Individual product line item"""
    description: str
    quantity: float
    unit: str  # e.g., "PCS", "KG", "CBM"
    unit_price: float
    total_price: float
    hs_code: str | None = None  # 8-digit HS code
    origin_country: str | None = None
    weight: float | None = None
    confidence_scores: Dict[str, float] = Field(default_factory=dict)
    # confidence_scores keys: "description", "quantity", "unit_price", "hs_code", etc.

class ContainerDetails(BaseModel):
    """Shipping container information"""
    container_number: str
    size: str  # e.g., "20'", "40'", "40HC"
    weight: float | None = None
    seal_number: str | None = None
    confidence: float = Field(ge=0.0, le=1.0, default=0.0)

class ShipmentDates(BaseModel):
    """Key dates from documents"""
    invoice_date: str | None = None  # ISO format or DD/MM/YYYY
    bol_date: str | None = None
    arrival_date: str | None = None
    confidence_scores: Dict[str, float] = Field(default_factory=dict)

class ExtractedData(BaseModel):
    """Complete extracted customs declaration data"""
    shipper: CompanyDetails
    consignee: CompanyDetails
    products: List[ProductItem]
    containers: List[ContainerDetails]
    dates: ShipmentDates
    invoice_total: float
    currency: str  # e.g., "USD", "EUR", "VND"
    invoice_number: str | None = None
    bol_number: str | None = None
    overall_confidence: float = Field(ge=0.0, le=1.0)

    model_config = {"json_schema_extra": { "example": { ... } }}
```

**Design Rationale:**
- All optional fields use `str | None` to allow LLM to indicate missing data
- Per-field confidence scores stored in nested dicts (matches LLM output structure)
- Overall confidence calculated as average of all field confidences (aggregation metric)
- JSON-serializable for storage in PostgreSQL JSONB column
- Pydantic validation ensures type safety and data integrity

### LLM Prompt Engineering Strategy

[Source: Acceptance Criteria 4, 6]

**Prompt Structure:**

**System Prompt:**
```
You are an expert customs data extraction assistant specializing in Vietnamese import declarations.
Your task is to extract structured data from OCR text of customs documents with high accuracy.

Documents you will process:
- Arrival Notice (AN): Contains vessel, container, arrival date, port information
- Bill of Lading (BOL): Contains shipper, consignee, container details, port of loading/discharge
- Certificate of Origin (CO): Contains exporter, importer, product descriptions, HS codes, quantities, origin country
- Commercial Invoice: Contains buyer, seller, product line items with prices, invoice total, currency

Extraction Guidelines:
1. Extract all fields specified in the schema
2. If a field is not found in the documents, set value to null and confidence to 0.0
3. Assign confidence scores (0.0-1.0) based on:
   - OCR text clarity (0.9-1.0 if clear, 0.5-0.8 if partially obscured)
   - Data consistency across documents (1.0 if values match, 0.7 if minor discrepancies)
   - Field completeness (1.0 if all required subfields present, lower if partial)
4. For product line items, extract from tables when available (typically in Invoice and CO)
5. For dates, preserve original format or convert to DD/MM/YYYY
6. For monetary values, extract currency separately from amounts

Output Format:
- Return ONLY valid JSON matching the ExtractedData schema
- Do NOT include explanations, markdown formatting, or code blocks
- Ensure all JSON keys match schema field names exactly
```

**User Prompt Template:**
```
Extract customs declaration data from the following documents:

=== ARRIVAL NOTICE (AN.pdf) ===
{ocr_result_an.text}

=== BILL OF LADING (BOL.pdf) ===
{ocr_result_bol.text}

=== CERTIFICATE OF ORIGIN (CO.pdf) ===
{ocr_result_co.text}

=== COMMERCIAL INVOICE (INVOICE.jpg) ===
{ocr_result_invoice.text}

Extract the following information:
1. Shipper details (company name, address, tax ID from BOL/Invoice)
2. Consignee details (company name, address, tax ID from BOL/Invoice)
3. Product line items from Invoice/CO tables:

4. Container details from AN/BOL (container numbers, sizes, weights, seal numbers)
5. Dates: Invoice date, BOL date, Arrival date (from respective documents)
6. Invoice total and currency

Return JSON matching this schema:
{ExtractedData.model_json_schema()}
```

### Error Handling Strategy

[Source: Acceptance Criteria 7, architecture/error-handling-strategy.md]

**Custom Exception Design:**
```python
# backend/src/core/errors.py

class OpenRouterException(Exception):
    """Raised when OpenRouter API call fails"""
    def __init__(
        self,
        message: str,
        status_code: int | None = None,
        original_error: Exception | None = None,
        retry_count: int = 0
    ):
        self.message = message
        self.status_code = status_code
        self.original_error = original_error
        self.retry_count = retry_count
        super().__init__(self.message)
```

**Retry Logic Configuration:**
```python
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type
)
import httpx

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=2, min=2, max=10),
    retry=retry_if_exception_type((httpx.TimeoutException, httpx.HTTPStatusError))
)
async def _call_openrouter_api(self, messages: list, model: str) -> dict:
    """Call OpenRouter API with retry logic"""
    try:
        response = await self.client.post(
            "/chat/completions",
            json={
                "model": model,
                "messages": messages,
                "temperature": 0.1,
                "max_tokens": 4096
            },
            timeout=60.0
        )
        response.raise_for_status()
        return response.json()
    except httpx.HTTPStatusError as e:
        if e.response.status_code == 401:
            # Don't retry auth errors
            raise OpenRouterException(
                "Invalid OpenRouter API key. Please check configuration.",
                status_code=401,
                original_error=e
            )
        elif e.response.status_code == 429:
            # Rate limit - will retry with backoff
            sentry_sdk.add_breadcrumb(
                category="llm",
                message="OpenRouter rate limit hit, retrying...",
                level="warning"
            )
            raise
        else:
            raise OpenRouterException(
                f"OpenRouter API error: {e.response.text}",
                status_code=e.response.status_code,
                original_error=e
            )
```

**Error Message Guidelines:**
- **Rate Limit (429)**: "OpenRouter API rate limit exceeded. Processing will retry automatically."
- **Timeout**: "OpenRouter API timeout. Network may be slow. Retrying..."
- **Invalid API Key (401)**: "Invalid OpenRouter API key. Please check OPENROUTER_API_KEY in environment variables."
- **Invalid JSON Response**: "LLM returned invalid response format. Unable to parse extraction results. Raw response logged to Sentry for debugging."
- **Pydantic Validation Error**: "Extracted data validation failed: {specific field errors}. Partial data may be available."

### Multi-Document Extraction Strategy

[Source: Acceptance Criteria 3, 4]

**Processing Multiple OCR Results:**

For a complete declaration, the LLM needs OCR results from all 4 documents:
1. `AN.pdf` - Arrival Notice
2. `BOL.pdf` - Bill of Lading
3. `CO.pdf` - Certificate of Origin
4. `INVOICE.jpg` - Commercial Invoice

**Prompt Construction for Multi-Document Input:**
```python
def format_multi_document_prompt(
    ocr_an: OCRResult,
    ocr_bol: OCRResult,
    ocr_co: OCRResult,
    ocr_invoice: OCRResult
) -> str:
    """Format OCR results from all 4 documents into single extraction prompt"""

    prompt = "Extract customs declaration data from the following documents:\n\n"

    # Add each document with clear section headers
    prompt += f"=== ARRIVAL NOTICE ({ocr_an.file_name}) ===\n"
    prompt += f"{ocr_an.text}\n\n"

    # Include tables if present (formatted as markdown)
    if ocr_an.tables:
        prompt += "Tables from Arrival Notice:\n"
        for table in ocr_an.tables:
            prompt += format_table_as_markdown(table) + "\n"

    prompt += f"=== BILL OF LADING ({ocr_bol.file_name}) ===\n"
    prompt += f"{ocr_bol.text}\n\n"

    prompt += f"=== CERTIFICATE OF ORIGIN ({ocr_co.file_name}) ===\n"
    prompt += f"{ocr_co.text}\n\n"

    # CO often contains product table - critical for extraction
    if ocr_co.tables:
        prompt += "Product Tables from Certificate of Origin:\n"
        for table in ocr_co.tables:
            prompt += format_table_as_markdown(table) + "\n"

    prompt += f"=== COMMERCIAL INVOICE ({ocr_invoice.file_name}) ===\n"
    prompt += f"{ocr_invoice.text}\n\n"

    # Invoice tables contain pricing - essential for extraction
    if ocr_invoice.tables:
        prompt += "Line Items from Commercial Invoice:\n"
        for table in ocr_invoice.tables:
            prompt += format_table_as_markdown(table) + "\n"

    # Add extraction instructions
    prompt += "\n" + get_extraction_instructions()

    return prompt
```

**Token Optimization:**
- Average prompt: ~1,200 tokens (OCR text is already compact)
- If prompt exceeds 8,000 tokens (rare), truncate least critical sections (e.g., duplicate information across documents)
- Monitor token usage and optimize prompt template based on usage patterns
