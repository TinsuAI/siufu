# Story 3.2: User Authentication

## Status
**Done**

## Story
**As a** user,
**I want** to log in with email and password,
**so that** my declarations are secure and tracked to my account.

## Acceptance Criteria
1. Login screen with email and password input fields, "Remember me" checkbox, "Login" button
2. Backend endpoint `POST /api/auth/login` validates credentials and returns JWT token
3. JWT token stored in httpOnly cookie with configurable expiration (default 8 hours per NFR19)
4. Protected routes redirect to login if user not authenticated
5. Backend middleware validates JWT on protected endpoints and attaches user context
6. User registration endpoint `POST /api/auth/register` creates new user with bcrypt password hashing
7. Session persists across browser refreshes via cookie
8. Logout endpoint `POST /api/auth/logout` clears cookie and invalidates session
9. Clear error messages for failed login ("Invalid email or password")
10. For MVP: Single user account seeded in database (client's primary user)

### Architecture Context

#### Authentication Flow (from architecture documents)

**Login Sequence:**
1. User enters email/password on `/login` page
2. Frontend sends POST to `/api/auth/login`
3. Backend validates credentials against `users` table
4. Backend creates JWT token with user_id, role, organization_id in payload
5. Backend sets httpOnly cookie with token (8-hour expiration)
6. Backend returns LoginResponse with user profile
7. Frontend stores user in Zustand auth store
8. Frontend redirects to `/declarations`

**Protected Route Access:**
1. Frontend middleware checks authentication on navigation
2. Middleware calls `GET /api/auth/me` (sends cookie automatically)
3. Backend validates JWT from cookie
4. If valid, backend returns user profile; frontend allows navigation
5. If invalid/expired, backend returns 401; frontend redirects to `/login`

**Session Persistence:**
- JWT stored in httpOnly cookie (not accessible to JavaScript - XSS protection)
- Cookie persists across browser sessions (unless user clears cookies)
- On app load, frontend calls `GET /api/auth/me` to restore user state
- If token expired (>8 hours), user must re-login

[Source: docs/architecture/security-and-performance.md#authentication-security]

**Backend:**
- **JWT Library:** python-jose 3.3 - JWT token creation and validation

- **Token Expiration:** 8 hours (configurable via environment variable)

**Frontend:**
- **Cookie Handling:** Automatic (browser sends httpOnly cookie with every request)

    required: true
    content:

        schema:
          type: object
          properties:
            email: { type: string, format: email }
            password: { type: string }
  responses:
    200:
      description: Login successful
      headers:
        Set-Cookie:
          description: httpOnly cookie with JWT token
          schema:
            type: string

            $ref: '#/components/schemas/User'

#### Security Requirements

**JWT Configuration:**
- **Secret Key:** Random 256-bit key (generate with `openssl rand -hex 32`)
- **Algorithm:** HS256 (symmetric signing)
- **Expiration:** 8 hours (28800 seconds)
- **Cookie Settings:**
  - `httpOnly: true` - Not accessible via JavaScript (XSS protection)
  - `secure: true` - Only sent over HTTPS (use `false` in local dev)
  - `samesite: "strict"` - CSRF protection
  - `path: "/"` - Cookie sent with all requests

**Password Requirements:**
- Minimum 8 characters (enforced in frontend and backend validation)
- bcrypt hashing with 12 rounds (cost factor)
- No password strength requirements for MVP (Phase 2 enhancement)

**Error Messages:**
- NEVER reveal whether email exists or password is wrong
- Always return generic "Invalid email or password" on login failure
- Prevents user enumeration attacks

#### Backend Repository Pattern

**UserRepository Example:**
```python
# repositories/user_repository.py
class UserRepository:
    def __init__(self, db: AsyncSession):
        self.db = db

    async def get_by_email(self, email: str) -> Optional[User]:
        stmt = select(User).where(User.email == email, User.is_active == True)
        result = await self.db.execute(stmt)
        return result.scalar_one_or_none()

    async def create(self, email: str, hashed_password: str, full_name: str, organization_id: UUID) -> User:
        user = User(
            email=email,
            hashed_password=hashed_password,
            full_name=full_name,
            role='processor',
            organization_id=organization_id,
        )
        self.db.add(user)
        await self.db.commit()
        await self.db.refresh(user)
        return user
```

#### Important Notes for Dev Agent

1. **NEVER store JWT in localStorage** - Use httpOnly cookies ONLY. This is a critical security requirement.

2. **Password hashing is slow by design** - bcrypt intentionally takes ~100ms to hash. Do NOT try to "optimize" this. It's a security feature.

3. **Token expiration is 8 hours** - Users will be auto-logged out after 8 hours of inactivity. This is intentional per NFR19.

4. **MVP has single user account** - Do NOT implement user management UI. Registration endpoint exists for testing, but production will have only the seeded demo user.

5. **"Remember me" checkbox is UI-only** - Check the box but don't implement functionality. All sessions are 8 hours regardless. Phase 2 may implement 30-day refresh tokens.

6. **Use FastAPI TestClient for auth tests** - TestClient automatically handles cookies, making auth testing straightforward.

7. **Middleware runs on EVERY request** - Next.js middleware must be fast (<50ms). Do NOT add heavy logic.

8. **Error messages are generic on purpose** - "Invalid email or password" prevents attackers from determining valid emails.

9. **Cookie works automatically** - Browser sends httpOnly cookie with every request. No manual header management needed in frontend.

10. **Protected routes include ALL declaration routes** - /declarations, /upload, /declarations/[id]/review, /analytics, /knowledge-base all require authentication.
