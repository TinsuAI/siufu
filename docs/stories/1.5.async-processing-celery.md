# Story 1.5: Async Processing with Celery

## Status
Done

## Story

**As a** user,
**I want** declaration processing to happen in the background,
**so that** I can continue working while the system processes documents without the browser hanging.

## Acceptance Criteria

1. Celery 5.4 worker configured with Redis as message broker
2. Celery worker starts successfully in Docker Compose and connects to Redis
3. Background task `process_declaration_task(declaration_id: int)` orchestrates full processing pipeline
4. Task progresses through states: PENDING → PROCESSING_OCR → PROCESSING_LLM → VALIDATING → COMPLETED or FAILED
5. Task status and progress stored in database and queryable via API endpoint `GET /api/declarations/{id}/status`
6. Task results (extracted data JSON) stored in Declaration model upon completion
7. Failed tasks log errors to Sentry and update Declaration status to FAILED with error message
8. Frontend can poll status endpoint to show real-time processing progress (per NFR1: <90 sec processing time)

### Celery Task Structure

[Source: docs/architecture/backend-architecture.md#celery-task-structure]

**Task Pattern to Follow:**
```python
# backend/src/workers/declaration_processor.py
from src.core.celery_app import celery_app
import asyncio

@celery_app.task(bind=True, max_retries=3)
def process_declaration_task(self, declaration_id: str):
    try:
        result = asyncio.run(_process_declaration_async(declaration_id))
        return result
    except Exception as exc:
        logger.error(f"Processing failed: {exc}")
        raise self.retry(exc=exc, countdown=60)

async def _process_declaration_async(declaration_id: str):
    # Stage 1: OCR (20-30s)
    ocr_service = OCRService()
    ocr_results = await asyncio.gather(*[
        ocr_service.process_document(file['path'])
        for file in pdf_files
    ])

    # Stage 2: LLM Extraction (25-40s)
    extraction_service = ExtractionService()  # This is LLMService
    extracted_data = await extraction_service.extract_structured_data(ocr_results)

    # Update declaration
    await repo.update_status(declaration_id, 'READY_FOR_REVIEW', progress=1.0)

    return {'status': 'READY_FOR_REVIEW'}
```

**Critical Implementation Details:**
- Celery tasks are synchronous functions, but can wrap async code using `asyncio.run()`
- Use `bind=True` to access `self` for retry logic
- Set `max_retries=3` to prevent infinite retry loops
- Return dict from task for result tracking
- Update database at each stage to enable progress polling

### Declaration Status State Machine

[Source: docs/architecture/data-models.md#model-declaration]

**Status Flow:**
```
UPLOADED (initial)
    ↓ (task started)
PROCESSING_OCR (progress: 0.1)
    ↓ (OCR complete)
PROCESSING_LLM (progress: 0.4)
    ↓ (LLM complete)
VALIDATING (progress: 0.7)
    ↓ (validation complete)
READY_FOR_REVIEW (progress: 1.0)
    ↓ (user action)
APPROVED or REJECTED
```

**Failure Path:**
```
Any status → FAILED (progress: 0.0, processing_error set)
```


### Error Handling Strategy

[Source: docs/architecture/error-handling-strategy.md]

**Error Classification for Retry Logic:**

**Transient Errors (Retry):**
- `DocumentAIException` with status_code 429 (rate limit)
- `OpenRouterException` with status_code 429 (rate limit)
- `httpx.TimeoutException` (network timeout)
- `redis.exceptions.ConnectionError` (Redis temporarily unavailable)

**Permanent Errors (Do Not Retry):**
- `FileNotFoundError` (uploaded file missing)
- `ValueError` (invalid declaration data)
- `DocumentAIException` with status_code 401 (invalid credentials)
- `OpenRouterException` with status_code 401 (invalid API key)

**Retry Configuration:**
- Max retries: 3
- Backoff: 60s, 120s, 240s (exponential)
- After max retries: Mark declaration as FAILED permanently
