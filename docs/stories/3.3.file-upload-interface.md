# Story 3.3: File Upload Interface

## Status
**Done** (All QA issues resolved, all 32 tests passing)

## Story
**As a** user,
**I want** a drag-and-drop interface to upload all 6 required files,
**so that** I can easily submit documents for processing.

## Acceptance Criteria
1. Upload screen (`/upload`) displays 6 labeled drop zones: Arrival Notice (PDF), Bill of Lading (PDF), Certificate of Origin (PDF), Invoice (PDF/Image), Good List (Excel), EXIM Tariff (Excel)
2. Drag-and-drop functionality works for all drop zones with visual feedback (highlight on drag-over)
3. Alternative: Click to open file browser for each zone
4. Visual checklist shows which files uploaded (✓ green checkmark when file added)
5. File type validation on frontend before upload (show error if wrong type)
6. File size validation (PDFs max 10MB, images max 5MB, Excel max 2MB) with clear error messages
7. "Process Declaration" button enabled only when all 6 files uploaded
8. Clicking "Process Declaration" uploads files to `POST /api/declarations/upload` and triggers processing
9. After upload, user redirected to processing status screen showing declaration ID
10. Error handling: Display clear messages if upload fails (network error, validation error)

#### File Upload Workflow (from docs/architecture/core-workflows.md)

**Happy Path Sequence:**
1. User navigates to `/upload` page (protected route)
2. User drags and drops 6 files OR clicks to browse and select files
3. Frontend validates file types and sizes client-side
4. User clicks "Process Declaration" button
5. Frontend sends POST request to `/api/declarations/upload` with FormData
6. Backend validates files, stores them in Docker volume at `./data/uploads/{declaration_id}/`
7. Backend creates Declaration record in database with status UPLOADED
8. Backend returns declaration ID
9. Frontend navigates to `/declarations/{id}` (processing status screen)
10. Backend triggers Celery task for processing (Story 1.7)

**Error Scenarios:**
- Invalid file type → Show error inline on drop zone
- File size exceeded → Show error with actual vs max size
- Network error → Show error banner with retry button
- Backend validation error → Parse error response and show specific field errors

**Timing Target:**
- Upload phase should complete within 5-10 seconds for all 6 files

[Source: docs/architecture/core-workflows.md#workflow-1-complete-declaration-processing]

#### Important Implementation Notes

1. **File Upload Security:**
   - ALWAYS validate file types on both client and server
   - Use MIME type detection on backend, not just file extension
   - Never trust client-side validation alone
   - Backend in Story 1.6 already implements server-side validation

2. **FormData Construction:**
   - Use native browser `FormData` API
   - Append files with exact field names expected by backend (snake_case)
   - Set proper `Content-Type: multipart/form-data` (browser handles automatically)

3. **User Experience:**
   - Provide immediate feedback for file selection (checkmark, file name)
   - Show clear validation errors with actionable messages
   - Disable upload button while request in progress
   - Provide visual progress indicator during upload

4. **Performance:**
   - Files are uploaded in single request (not one-by-one)
   - Use async/await for upload to avoid blocking UI
   - Consider upload progress tracking for large files (optional)

5. **Accessibility:**
   - Drag-and-drop must have click-to-browse alternative
   - All interactive elements must be keyboard accessible
   - Use ARIA labels for screen readers
   - Ensure color contrast meets WCAG AA standards

6. **Testing:**
   - Mock `File` objects in tests using `new File(['content'], 'filename.pdf', { type: 'application/pdf' })`
   - Mock API responses for upload success and error scenarios
   - Test validation edge cases (0 bytes, exactly at limit, over limit)
   - Use Vitest with React Testing Library, NOT Jest

7. **Navigation:**
   - After successful upload, navigate to `/declarations/[id]` where `[id]` is returned declaration ID
   - Use Next.js App Router `useRouter()` from `next/navigation` (NOT `next/router`)
   - Pass declaration ID in URL, not state

8. **Error Handling:**
   - Parse backend error responses following RFC 7807 Problem Details format
   - Display field-specific errors next to relevant drop zones
   - Provide retry mechanism for network errors
   - Log errors to Sentry (already configured in Story 1.2)
