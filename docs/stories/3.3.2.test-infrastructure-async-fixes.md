## Story

### Context

During QA review of Story 3.3.1, a test infrastructure regression was discovered. 4 of 11 security tests fail with `RuntimeError: Event loop is closed` when run together, but pass when run individually. This indicates a fundamental issue with how async fixtures manage event loop lifecycles.

This regression was introduced during recent development work (OCRResult bug fixes, container rebuilds) and affects the ability to verify security measures and run comprehensive test suites.

---

## Problem Statement

### Current Behavior

**Symptom**: Tests fail with event loop closure errors during cleanup
```
RuntimeError: Event loop is closed
  File "/usr/local/lib/python3.12/asyncio/base_events.py", line 545, in _check_closed
    raise RuntimeError('Event loop is closed')
```

**Pattern**:
- Tests pass individually: `pytest tests/security/test_upload_security.py::test_rejects_path_traversal_in_filename` ✅
- Tests fail when run together: `pytest tests/security/test_upload_security.py` ❌

**Affected Tests** (4 of 11):
1. `test_rejects_path_traversal_in_filename`
2. `test_rejects_file_exceeding_size_limit_pdf`
3. `test_rejects_more_than_20_co_files`
4. `test_sanitizes_special_characters_in_filename`

**Common Factor**: All failing tests perform full file upload workflows with database operations

### Root Cause Analysis

**Issue**: Session-scoped `test_engine` fixture conflicts with function-scoped pytest-asyncio event loops

**Why it happens**:
1. pytest-asyncio creates new event loop per test function
2. `test_engine` (session-scoped) creates async database connections tied to first test's loop
3. Subsequent tests run in different event loops
4. Database cleanup attempts to use closed event loop from previous test
5. Runtime error during fixture teardown

**Evidence**:
- Error occurs during `asyncpg.connection.close()` in cleanup phase
- Warning: `coroutine 'Connection._cancel' was never awaited`
- Tests contaminate each other's async context

**Fixture Best Practices** (Critical for this story):
1. **Session-scoped fixtures**: Create once per test session (database engine, event loops)
2. **Function-scoped fixtures**: Create/destroy per test (database sessions, transactions)
3. **Async fixture cleanup**: Always use `await` in teardown, never close event loops prematurely
4. **Transaction isolation**: Preferred pattern - wrap tests in transactions, rollback after each test

### Key Technical Context

**Root Cause Summary**:
- Session-scoped `test_engine` creates async connections tied to first test's event loop
- pytest-asyncio creates new event loop for each function-scoped test
- Subsequent tests run in different event loops, causing cleanup to fail with "Event loop is closed"

**Recommended Solution** (Transaction-Based Isolation):
- Keep session-scoped engine (single create/drop of tables)
- Function-scoped db_session wraps each test in a transaction
- Rollback transaction after test (fast cleanup, proper isolation)
- Industry standard pattern used by FastAPI, SQLAlchemy documentation

**Alternative Options Evaluated**:
- Option 2: pytest-asyncio loop_scope configuration (requires pytest-asyncio >= 0.21.0)
- Option 3: Separate test database per worker (for pytest-xdist parallel execution)

## Technical Approach

### Investigation Summary

**Attempts Made** (Story 3.3.1 QA Review):
1. ❌ Modified `db_session` fixture with explicit try/finally cleanup
2. ❌ Changed `test_engine` scope from session to function (causes slow tests)
3. ❌ Added proper `async_client` fixture with ASGITransport
4. ❌ Added event loop policy fixture
5. ❌ Installed pytest-xdist==3.6.1 (caused database concurrency issues)

### Recommended Solutions

**Option 1: Transaction-Based Test Isolation** (Recommended)
- Use single session-scoped engine
- Wrap each test in transaction, rollback after test
- Prevent table create/drop per test
- Example: FastAPI docs pattern

**Benefits**:
- Fast (no table recreation)
- Proper event loop management
- Industry standard pattern

**Implementation**:
```python
@pytest.fixture(scope="session")
async def test_engine():
    engine = create_async_engine(TEST_DATABASE_URL)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    yield engine
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all)
    await engine.dispose()

@pytest.fixture(scope="function")
async def db_session(test_engine):
    connection = await test_engine.connect()
    transaction = await connection.begin()
    session = async_sessionmaker(bind=connection)()

    yield session

    await session.close()
    await transaction.rollback()
    await connection.close()
```

**Option 2: pytest-asyncio Loop Scope Configuration**
- Configure loop scope per fixture
- Use `pytest_asyncio.fixture(loop_scope="session")` for engine
- Requires pytest-asyncio >= 0.21.0

**Option 3: Separate Test Database Per Worker**
- For parallel execution with pytest-xdist
- Each worker gets unique database
- Prevents database contention
